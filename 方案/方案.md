**SPEC：three-bucket-dca / 三仓定投计划**

**Problem Statement**
你现在有三个分散的定投项目：

- `BTC_DDCA_old999`：BTC 周期进攻仓
- `CRCL_DCA`：CRCL 加密金融成长仓
- `US_INDEX_DCA`：QQQM + VOO 美股长期底仓

这些项目分别维护规则、数据、提醒和执行逻辑。新增 `STRC` 后，如果继续分散维护，会出现：

- 定投规则分散，难以统一查看
- 执行记录分散，难以计算真实持仓成本和收益
- 提醒渠道不统一
- 历史数据无法集中复盘
- VPS 部署和自动化任务维护成本高

目标是创建新仓库：

```text
D:\code-web3\self\three-bucket-dca
```

仓库名：

```text
three-bucket-dca
```

页面标题：

```text
三仓定投计划
```

系统模块名：

```text
DCA Tracker
```

整合四个仓位：

- BTC：周期进攻仓
- CRCL：加密金融成长仓
- QQQM + VOO：美股长期底仓
- STRC：BTC 现金流仓

**Proposed Solution**
构建一个轻量级本地/VPS Web 系统，采用：

```text
FastAPI + 原生 HTML/JS/CSS + SQLite
```

系统由三部分组成：

1. **统一规则引擎**
   - 抽取 BTC、CRCL、QQQM+VOO 三个旧项目的核心定投规则。
   - 新增 STRC 规则。
   - 每个仓位独立频率、独立金额、独立判断逻辑。
   - 输出完整决策卡片。

2. **Web 驾驶舱**
   多页面结构：

   - `/`：三仓总览看板
   - `/transactions`：交易记录新增/编辑/删除
   - `/settings`：配置展示
   - `/rules`：完整规则说明

   看板展示：

   - 三仓决策卡
   - 当前价格
   - 建议动作
   - 建议金额
   - 原因说明
   - 下次执行窗口
   - 持仓成本
   - 累计投入
   - 当前市值
   - 浮盈浮亏
   - 收益率
   - 本月资金计划
   - 执行记录

3. **自动提醒与部署**
   - Linux VPS 部署。
   - 每 5 分钟运行一次更新任务。
   - 只在定投日当天推送一次提醒。
   - 所有提醒统一使用企业微信机器人。
   - 提醒时间按 `Asia/Shanghai` 北京时间。
   - 使用 SQLite 记录提醒发送历史，避免 5 分钟任务重复推送。

**仓位与资产模型**
采用“仓位”和“资产”分离：

- `BTC_CYCLE`
  - 显示名：BTC：周期进攻仓
  - 资产：BTC

- `CRCL_GROWTH`
  - 显示名：CRCL：加密金融成长仓
  - 资产：CRCL

- `US_INDEX_CORE`
  - 显示名：QQQM + VOO：美股长期底仓
  - 资产：QQQM
  - 资产：VOO

- `STRC_CASHFLOW`
  - 显示名：STRC：BTC 现金流仓
  - 资产：STRC

交易记录按资产记录，统计可按仓位聚合。

**STRC 规则**
STRC 使用 Yahoo Finance ticker：

```text
STRC
```

定投规则：

- 每月金额：`$100`
- 定投提醒日：每月 `14` 日，北京时间
- 买入判断：
  - `$98 <= price <= $101`：建议买入 `$100`
  - `price > $103`：暂停
  - `price < $95`：风险复盘，不自动买
  - 其它价格：等待

STRC 不做实时价格触发推送，只在每月 14 日推送提醒。

**旧项目迁移**
第一阶段必须审计三个旧项目：

```text
D:\code-web3\self\BTC_DDCA_old999
D:\code-web3\self\CRCL_DCA
D:\code-web3\self\US_INDEX_DCA
```

必须产出：

- 规则清单
- 数据源清单
- 历史数据清单
- 推送逻辑清单
- 可迁移文件清单
- 迁移映射说明

迁移要求：

- 需要迁移历史交易/执行数据。
- 只要是机器可解析的数据，都必须 100% 自动迁移。
- 包括 CSV、JSON、SQLite、Excel、固定格式日志。
- 不包括截图、自由文本、无法稳定解析的控制台输出。
- 迁移失败则项目不能视为完成。

迁移后的数据进入新 SQLite 账本。

**交易账本**
使用 SQLite 保存交易记录。

交易记录字段：

- 日期
- 仓位
- 资产/ticker
- 金额 USD
- 价格 USD
- 份额
- 备注纯文本
- 创建时间
- 更新时间

页面支持：

- 新增交易
- 编辑交易
- 删除交易

所有金额统一 USD。

持仓和收益完全基于系统内交易记录计算。

**写操作保护**
只保护写操作。

- 看板只读无需登录。
- 新增交易需要 token。
- 编辑交易需要 token。
- 删除交易需要 token。
- token 每次操作都要输入。
- token 不保存在浏览器。
- token 存在项目 `.env` 文件中。

示例：

```env
DCA_WRITE_TOKEN=change-me
WEWORK_BOT_WEBHOOK=https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx
```

项目需要提供：

```text
.env.example
```

并确保：

```text
.env
```

不提交 git。

**企业微信推送**
所有仓位使用企业微信机器人推送。

推送规则：

- 只在各仓位定投日推送。
- 定投日当天推一次即可。
- 不检查当天是否已执行。
- 不重复催。
- 不提前一天提醒。
- 不做价格触发型实时提醒。
- 使用 SQLite 记录提醒发送历史，避免重复推送。

STRC 定投日：

```text
每月 14 日，北京时间
```

BTC、CRCL、QQQM+VOO 的定投日沿用旧项目规则。

**SQLite 备份**
首版必须包含备份策略：

- 每次更新前自动备份 SQLite。
- 备份目录：

```text
backups/
```

- 保留最近 `30` 份。
- 超过 30 份自动删除最旧备份。

**Non-goals**
首版明确不做：

- 不做自动交易
- 不接券商下单

- 不做多用户权限
